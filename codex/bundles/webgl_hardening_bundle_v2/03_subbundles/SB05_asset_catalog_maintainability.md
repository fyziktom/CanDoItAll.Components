# SB05 — Asset Catalog Maintainability

## Goal

Prevent sandbox asset catalog files from becoming long, fragile, manually maintained lists.

## Current risk

`WebGlSandboxAssetCatalogFactory.cs` mixes core assets, building/person/prop variants, external model metadata, performance hints, and helper methods. It will keep growing as more models are added.

## Implementation tasks

Refactor the sandbox catalog into smaller parts. Suggested split:

```text
WebGlSandboxAssetCatalogFactory.cs          // orchestration only
WebGlSandboxCoreAssets.cs                   // fallback, marker, primitive common assets
WebGlSandboxBuildingAssets.cs               // houses/services/building variants
WebGlSandboxPersonAssets.cs                 // agent/person variants
WebGlSandboxPropAssets.cs                   // props/trees/paths/wells/etc.
WebGlSandboxExternalModels.cs               // generated or hand-maintained manifest only
```

Keep each file under roughly 180 lines.

Improve the model inventory script so it can generate a machine-readable manifest:

```text
artifacts/webgl-runtime-hardening-v2/glb-inventory.json
```

Optionally generate a C# manifest from that JSON, but if generated code is committed, clearly mark it with `// <auto-generated />`.

## Acceptance criteria

- Catalog factory becomes orchestration-only.
- External model metadata is not duplicated in multiple places.
- Asset catalog tests still pass.
- Asset catalog page still displays primitive/model-low/model-high alternatives.
