# Semantic invariants - SB10

- Components remains domain-neutral; headless research-run semantics and CLI behavior live in Economy.
- New headless APIs must prefer catalog scenario ids and scenario sources over raw `experimentJsonPath`.
- Path-based runner APIs remain available only as legacy-compatible entry points and must report `scenarioSourceKind: legacy-path`.
- A catalog scenario id run must emit readiness, frame hashes, metrics/invariants, warnings, run summary, and reproducibility manifest artifacts in the output directory.
- The reproducibility manifest must be self-contained: it lists scenario id/source kind, status, run hash, frame hash chain, oracle coverage label, and sibling artifact hashes.
- CLI and batch output must surface readiness status, not just success/failure.
- Batch catalog runs must preserve status and run-hash maps keyed by scenario id.
- Pathless scenario-source materialization must be temporary and must not become the primary persisted source of truth.
- Proof must include failing-first evidence and non-placeholder artifacts generated by the production runner.
