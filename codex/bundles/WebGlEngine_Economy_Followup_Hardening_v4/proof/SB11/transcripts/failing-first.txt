# SB11 failing-first transcript

Semantic assertion: before SB11, `WebGlSceneView.OnParametersSet` used the full serialized scene/options payload as its lifecycle key. A large scene that changed object data without an explicit revision therefore issued a parameter-driven `CanDoItAll.webglScene.update` and paid the full payload serialization cost instead of relying on a revision/runtime key.

Command:

```powershell
dotnet test tests\CanDoItAll.Components.WebGlLib.Tests\CanDoItAll.Components.WebGlLib.Tests.csproj --no-restore --filter FullyQualifiedName~WebGlSceneViewExternalImportLifecycleTests.Large_scene_parameter_lifecycle_uses_revision_and_runtime_key_instead_of_full_payload
```

Failing-first result captured during SB11 implementation:

```text
Exit code: 1
Assert.DoesNotContain() Failure: Filter matched in collection
Collection:
  Invocation { Identifier = "CanDoItAll.webglScene.create", Arguments = ... }
  Invocation { Identifier = "CanDoItAll.webglScene.update", Arguments = ... }
Filter:
  invocation => invocation.Identifier == "CanDoItAll.webglScene.update"
```

The failure proves the pre-fix lifecycle path treated a 1000-object in-place payload mutation as a fresh scene update. The SB11 fix replaces large-scene lifecycle matching with a compact revision/runtime key and keeps the update suppressed until `WebGlSceneModel.Revision` or related compact-key fields change.
